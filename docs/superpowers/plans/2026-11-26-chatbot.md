# JSC Oscars chatbot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A member-only chat helper (how-to, stats and trivia, light jokes, quick links) backed by a Supabase Edge Function that calls Groq with tool calling.

**Architecture:** Pure, dependency-free TypeScript modules in `supabase/functions/_shared/chat/` hold all logic (links, prompt, model loop, limits, tools). A thin Deno entry `supabase/functions/chat/index.ts` wires auth, quota, Groq and Supabase. Vitest (run from `client/`) tests the pure modules by importing them across the folder boundary. The React UI calls the function through `client/src/api/chat.ts`.

**Tech Stack:** Supabase Edge Functions (Deno), Groq OpenAI-compatible chat API, Postgres (manual migration), React 19 + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-chatbot-design.md`
**UI mock:** `.superpowers/brainstorm/*/content/chat-ui-mock-v2.html` (phone and desktop).

## Global Constraints

- No teasing or roasting of members; light jokes only (spec anti-goal).
- Answers only from the guide or tool results; links only from the allowlist; never fabricate stats or links.
- Tools run with the signed-in member's JWT so existing RLS hides unreleased data; never use the service role for reads.
- Only member-visible, non-sensitive data goes to Groq (no emails, no votes, no unreleased results).
- Per-member daily cap default 20, global daily cap default 400 (env-configurable; set below the real Groq free quota once checked in the console).
- Message limits: max 500 characters per user message; only the last 12 messages are sent.
- Settings as env/secrets: `LLM_API_KEY`, `CHAT_MODEL`, `CHAT_FALLBACK_MODEL`, `CHAT_USER_CAP`, `CHAT_GLOBAL_CAP`. Model name and base URL are never hardcoded in logic.
- Manual SQL migrations are run by the user in the Supabase SQL Editor (existing project workflow).
- Client copy: sentence case, no "please", no "!" (UI tokens-only CSS scan test applies to React files).

## Review Focus

- Text from the database (idea names, descriptions) reaches the model via tools: the prompt tells the model tool results are data, never instructions. Test: a tool result containing "ignore your rules" does not alter the system prompt.
- The model emits a link marker to a path not in the allowlist, or malformed markers: shown as plain text, never as a button.
- Groq returns 429 on the main model, then also on the fallback: friendly "busy, try again in a minute", not a crash.
- Empty, whitespace-only, over-long, or non-string messages: rejected with a clear 400, no quota used.
- Two requests at once at the cap boundary: the quota function is atomic, so the cap is never exceeded.
- Missing, expired or invalid JWT: 401 and nothing else runs.
- Season results not released: tools say "not released yet" rather than returning an empty or partial answer.
