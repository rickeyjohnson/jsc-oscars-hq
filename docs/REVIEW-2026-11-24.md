Scope: read-only walk of the real code in `client/src` on `feat/voting-loop` for five journeys (new member, returning member, results day, committee, edge cases) before the group vote (Nov 25-26) and the ceremony (Dec 4). Nothing was run against a real Supabase project or a real phone; items marked "verify" are read from code and should be eyeballed once.

Paths are relative to `client/src/` unless they start with `supabase/` or `public/`.

All four failures are timezone assumptions in the tests (`lib/exportCsv.test.ts` x2, `lib/time.test.ts`, `ui/__tests__/countdown.test.ts` expect US Eastern), not app bugs. `eslint` reports 20 errors (e.g. `react-hooks/refs` in `ui/useRefetchOnFocus.ts`); none affect behavior.

Counts: **P0 = 3, P1 = 15, P2 = 59**.

## P1 - will hurt people on the day

### Voting loop

| # | Where | Problem | One-line fix |
|---|-------|---------|--------------|
| P1-1 | `pages/VotePage.tsx` (load effect, `Shell` states) | Load failure shows plain "Couldn't load this ballot." with no Try again; loading is bare text "Loading..." (not a skeleton, different from the `…` used elsewhere). A failure of the *members* fetch (group categories only) lands in the same `catch`, so the whole ballot is hidden even though detail and votes loaded. | Use `ErrorState` with retry; split the members fetch into its own try so the ballot still opens (group sheet shows its own error). ## P2 - polish, consistency, hygiene

### New member (landing, signup, claim, first Home)

- `pages/SignupPage.tsx`: the email path asks for a Username as well as the name pick; the member only ever sees their name. Drop the field (derive from email) or explain it.
- `pages/SignupPage.tsx`, `pages/ClaimNamePage.tsx`: with 14 chips at 320x568 the Google button / Create account sits below the fold; no sticky action. Make the action bar sticky.
- `ui/NameChips.tsx`: chips are colored with `pebbleFor(name)`; the same person's avatar everywhere else uses `avatarFallback(member.id)` (different hash key and a smaller palette). The color you pick on signup is not your color. Key by member id once known, or color all chips neutral.
- `pages/ResetPassword.tsx`: raw `error.message` shown (e.g. "Auth session missing" on an expired link); no confirm field or length hint. Map to "This link has expired. Request a new one" with a link to /login.
- `pages/LoginPage.tsx` (`ForgotPasswordModal`): raw error text for rate limits; the Forgot link is hidden until "Use email" is tapped when Google is on (fine, but say so in the Google-only view).
- `pages/HomePage.tsx` + `components/ProfileSetup.tsx`: a brand-new member's first Home opens straight into the "Add your photo" sheet; the skip flag is per device (localStorage), so it returns on a second device. First Home also has no "how voting works" hint. Store the skip in the profile row or show a dismissible card instead of a sheet.
- `pages/LandingPage.tsx`: matter-js physics with 13 balls on the landing page on every cold open (old phones); the count is 13, the group is 14.
- `pages/ComfirmedEmailPage.tsx`, `context/UserContenxt.tsx`: filename typos ("Comfirmed", "Contenxt"). Rename when quiet.

### Returning member (Home, Ballots, vote, review, submit, edit, close)

- `pages/home/widgets.tsx` (`Pending`): when there are no ballots at all it says "You're all caught up." Say "Nothing to vote on yet" when `summaries` is empty.
- `pages/home/widgets.tsx` (`YourStats`): three columns inside a one-column card (~140 px at 320 px): "Nominations" overflows. Stack to one column under `sm` or shorten to "Noms".
- `pages/HomePage.tsx`: `now` is frozen until data reloads, so a ballot that closes while Home is open still shows as pending with a Submit link. Tick `now` each minute.
- `ui/AppShell.tsx` (`usePendingCount`): the tab-bar badge refreshes only on tab focus; after finishing a ballot it stays until you leave and return. Refetch on route change.
- `pages/BallotsPage.tsx`, `api/ballots.ts`: the list is ordered by `closes_at` ascending, so under "All" the oldest closed ballots come first and the open one is lower down. Sort open first, then upcoming, then closed (newest first).
- `pages/BallotsPage.tsx`: `now = new Date()` is computed per render but never ticks; a ballot that closes while the page is open stays "Open" until the next refetch.
- `lib/time.ts` (`closedAtLabel`): "Voting closed at 3:00 PM" with no date; wrong for a ballot closed days ago. Add the day when older than today.
- `components/vote/CategoryVoteCard.tsx`: "YOU'RE IN THESE (CAN'T VOTE)" is ALL-CAPS 11 px in `text-label-3` (about 3.7:1 on the page background, below AA). Use `text-label-2` and sentence case. Same for the "(you)" chip in `GroupSheet.tsx`.
- `pages/VotePage.tsx`: the review step's "‹ Back" is a text link with `-ml-5`, unlike the NavBar chevron everywhere else; "Back" in the bottom bar means previous category. Rename the bottom one "Previous" or hide the link.
- `pages/VotePage.tsx`: `useRefetchOnFocus` refreshes the ballot detail but not `myVotes`; a vote made on another device is not reflected until reload (low risk, one device per person).
- `pages/VotePage.tsx` / `SubmitBallotPage.tsx`: the Submit page "Back to ballot" and Finish voting both push history, so Back loops between them. Use `replace`.
- `pages/SubmitBallotPage.tsx`: "Your picks are private" is not true for committee with DB access (`fetchAllVotes` returns voter_id + nominee_id). Say "Other members can't see your picks".
- `pages/SubmitBallotPage.tsx`, `pages/committee/ReleasePage.tsx`: loading is bare "Loading…" text on a flat screen; use the Skeleton pattern.
- Sheets (`ui/Sheet.tsx`): no history entry, so the Android system Back leaves the page instead of closing the sheet.

### Results day

- `pages/ResultsPage.tsx` (`run` depends on `member`): any identity refresh that gives a new `member` object (supabase can fire SIGNED_IN on tab refocus, which re-runs `UserDataProvider`) re-runs the whole load and flashes the skeleton. Depend on `member?.id`. (This may accidentally make P0-2 less visible, but it is not a reliable refresh.)
- `ui/Envelope.tsx` / `pages/ResultsPage.tsx`: `closeEnvelope` is recreated each render and is an effect dependency, so focus and the haptic can re-fire on re-render. `useCallback` it.
- Envelope is once per device (`hasSeenEnvelope` in localStorage); a member who opens Results on their laptop first sees no moment on their phone. Acceptable, but say so in the runbook.
- `pages/home/widgets.tsx` (`LatestWinners`, `LeaderboardPeek`) vs `ui/RevealCard.tsx`: Home colors a group winner by its first member's id and a non-member nominee by its name; Results keys the podium by `nominee_id`. The same group has two colors. Use `nomineeKey()` in both.
- `components/vote/CategoryVoteCard.tsx` / `lib/voting.ts` (`nomineePebbles`): groups and non-members take pebbles by list order, so a group is a different color on the ballot, Review, Home and Results. People are consistent; say so in the design notes or key groups by `nominee_id` everywhere.
- `ui/MemberAvatar.tsx` + `useMemberDirectory`: until the directory loads (or if it fails) the pebble is hashed from the typed name, then jumps to the id-based color. Visible as a color flash in Who voted and Member names. Render a neutral face until the directory resolves.
- `ui/Countdown.tsx` / `logic/countdown.ts`: after the ceremony time it shows "It's Oscar night" forever, including Dec 5+. Add a "Thanks for coming" state after ~6 h.
- Results tab "Leaderboard" for committee preview says "Stats appear after the envelope opens" while the Winners tab shows data: inconsistent.

### Edge cases and platform

- No global offline/slow indicator anywhere (`navigator.onLine` is only read in `VotePage.fail`). One thin banner in `AppShell` ("You're offline") would explain every failed screen.
- Empty seasons: `ResultsPage` says "Results are sealed." when there is no season at all (state `none`); `Pending` says "all caught up" (above). Use a distinct "Nothing here yet".
- Loading/empty/error patterns are consistent on Home/Ballots/Results/Committee (Skeleton + ErrorState); the exceptions are `VotePage`, `SubmitBallotPage`, `ReleasePage` (bare text) and `RequireCommittee` (legacy loader).
- `ui/ListRow.tsx`: titles and subtitles are `truncate`, so Settings rows like "In your browser's share menu, choose Add to Home Screen" and "Suggest a category for the next ballot" are cut off on phones. Allow two lines for subtitles.
- `pages/SettingsPage.tsx`, `components/EditProfileModal.tsx`: hard-coded "Ask Rickey or Kadin" in three places; fine for now, move to one constant in `ui/copy.ts`.
- `pages/ProfilePage.tsx` and `pages/SettingsPage.tsx` both have "Edit profile"; Settings also repeats "Customize Home". Keep it in one place.
- Desktop widths: Home is 1280 centered, Ballots/Results/You 1040, Screen column 720, Release 520. The content's left edge jumps between tabs at 1440-1920 (dead space on both sides). Pick 1040 for tabs and 1280 only for Home's 3-column grid, and left-align under the sidebar instead of centering.
- Tab bar / sidebar: both come from `TABS` so labels, icons and the badge match. Committee tools are in the sidebar on desktop but only inside You on mobile (fine); Settings is missing from the sidebar (reachable via You only).
- Page titles: every route has one via `lib/routeTitle.ts`; ballot-specific pages are generic ("Vote", "Manage ballot"). Add the ballot name.
- Dark-only contrast: `text-label-3` (about 3.7:1) is used for readable text in `CategoryVoteCard`, `GroupSheet`, `ManageOscarsModal` ("Click ..."), and placeholders. Reserve it for disabled/decorative.
- Type scale: `text-caption-2` (10.4 px, uppercase, tracking) is used for every widget title and many section headings; consider 11-12 px for the bottom of the scale.
- Service worker (`public/sw.js`): offline shows the cached app shell but every data call fails with no explanation (see the offline banner above); intended, just undocumented for members.
